What is a skill? A skill is a folder of instructions an agent loads only when relevant. The folder contains: A required SKILL.md file — the brain. It starts with a YAML header (the skill's name and description) and then the instructions in plain Markdown. Optional helper files in scripts/, references/, and assets/ subfolders. That's the whole format. It is deliberately boring — that's what makes it portable. A real example --- name: pdf description: Use this skill whenever the user wants to do anything with PDF files. This includes extracting text/tables, merging/splitting, rotating, filling forms, encrypting/decrypting, or producing a new PDF. --- When the user mentions a .pdf file or asks to produce one, use this skill. ## Reading text from a PDF Run scripts/extract_text.py <file> … The agent reads the name and description of every skill it has access to up front. When a user says "summarise this PDF for me", the agent matches the request to the pdf skill's description, loads the body of SKILL.md, and follows the instructions. No PDFs in the request? The agent never spends tokens reading the body. Why this is a big deal Capabilities ride with the model. Once a team has written an agent skill for, say, "audit a seller's catalogue against IM quality rules", that capability is available to anyone at IM whose agent has the skill loaded — not just the team that built it. Tiny context footprint. Discovery costs ~80 tokens per skill. You can hand an agent a hundred skills without bloating the context window. No code required to author one. The Claude UI has a "+ Create skill" flow under Customize → Skills that walks non-engineers through writing one. Same applies in ChatGPT now that OpenAI has adopted the standard. Portable across LLMs. Open standard since Dec 2025. The skill you write at IM works in Claude, ChatGPT, Cursor, VS Code Copilot, and Codex CLI. Our take: read this even if you only read one thing. Two paths depending on whether you're tech or non-tech. Both end in a working skill you can hand to the rest of the team. §1 — No-code path (Claude UI) You'll need a Claude Pro / Team / Enterprise account. Open Claude → click your profile → Customize → Skills. Click + → + Create skill. The UI walks you through: name, description, and the instructions. It also lets you attach reference files. When you save, Claude packages it as a folder behind the scenes — you don't have to think about the file structure. Test it: start a new chat and give Claude a prompt that should trigger your skill. If Claude doesn't pick it up, your description probably needs to be sharper — see 03-what-makes-a-great-skill.md. Our take: Even if you can write code, try the UI path first. The form forces you to phrase the description as an activation selector, which is the #1 thing skill authors get wrong. Official walkthroughs: How to create custom Skills (Claude Help Center) ↗ — the canonical UI tutorial. Use Skills in Claude (Claude Help Center) ↗ — how to enable and invoke them once installed. §2 — SKILL.md path (write the file yourself) Two sub-paths: write it from scratch, or let the skill-creator skill do the heavy lifting. §2a — Have Claude write it for you (recommended) Anthropic ships a meta-skill called skill-creator — its only job is to generate skills. Source: skill-creator/SKILL.md on GitHub ↗. Drop this into Claude Code (or the Claude Agent SDK) and ask it to "create a skill for X". It'll ask the right questions, generate the folder, draft the YAML header, and structure the instructions. Also packaged as the skill-creator plugin ↗. Third-party version on Smithery: claude-skill-creator ↗. Our take: This is the fastest way to get a skill that follows the canonical structure. Iterate on its output rather than start from a blank page. §2b — Author it by hand Minimum viable SKILL.md: --- name: bl-quality-auditor description: Use this skill when the user asks to audit a seller's BL (Business Listing) for quality issues — missing ISQs, incorrect MCAT mapping, weak product descriptions, or non-compliant images. Returns a structured issue list with severity scores. --- When invoked, do the following: 1. Read the BL identifier or URL the user provided. 2. Run scripts/fetch_bl.py <id> to pull the listing's current state. 3. Check each of: ISQ completeness, MCAT mapping, description quality, image compliance. Use references/quality-rules.md for the exact thresholds. 4. Produce a Markdown report grouped by severity. Always include a "what to fix first" section at the top. ## Inputs - BL ID (numeric) or URL ## Outputs - Markdown report. Optionally a CSV with one row per issue. Then create the folder: bl-quality-auditor/ ├── SKILL.md ├── scripts/ │ └── fetch_bl.py └── references/ └── quality-rules.md ZIP the folder and upload via the Claude UI (Customize → Skills → +), or drop it into your Claude Code project's .claude/skills/ directory. Field reference name (required): short, snake-case or kebab-case identifier. The agent uses this in tool calls. description (required): 1–2 sentences. Phrase it as a selector — "use this skill when…". Concrete trigger words help. Optional frontmatter fields you may see in the wild: version, license, requires, tags. The spec is at agentskills.io/specification ↗. Where the skill lives at runtime In Claude UI: under Customize → Skills, scoped to you or the org. In Claude Code: drop the folder under .claude/skills/ of your project (or under ~/.claude/skills/ for global skills). In a Cowork plugin: bundle one or more skills inside the plugin manifest. In VS Code Copilot: see Use Agent Skills in VS Code ↗. In OpenAI Codex / ChatGPT: see Agent Skills — Codex ↗. §3 — Sanity check before you ship Run through these before you call it done: The description field tells the agent when to use the skill (not what it does). If a colleague reads only the description, can they predict when it'll fire? SKILL.md body is under ~500 lines (split into references/ if longer). Scripts in scripts/ actually run end-to-end on the demo data. You've tested at least 2 prompts that should trigger it and 1 that shouldn't. The skill is named generically enough to be reused in another IM workflow (this is what pushes axis 5 from 4 → 5).
